# Runbook: origin errors (5xx from behind the edge)

**Alert:** `origin_errors` (`real_origin_monitoring`), or users report 502/504.

## 1. Edge or origin?
- `origin_errors.sql`: minutes with more than 5% origin 5xx, with p95 origin latency.
- A 5xx with `OriginResponseStatus = 0` was generated by Cloudflare itself (tunnel or connection
  problem); see [tunnel-down](tunnel-down.md).
- 502/504 with a real origin status and high latency is the application or what it depends on.

## 2. Origin side
- The most recent deploy: roll back first, investigate second.
- Database and connection pools (for example PgBouncer saturation), downstream timeouts.
- Under heavy load: check that static assets are actually cached (`cache_efficiency.sql`). A
  broken cache rule sends all asset traffic to the origin.

## 3. Afterwards
Record the timeline from the logs: first 5xx, mitigation, recovery.
